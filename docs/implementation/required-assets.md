# Required image assets for the tracer

Design checkpoint, 12 September 2026. Based on `a6141d38cd7ae8947b2398d2e44b8df80fe665b6`; this document proposes implementation and tests, and does not claim asset playback is implemented or verified. Scope is one bounded image path through editing, compilation, preview, and immutable offline export. No asset providers, library, network loader, native protocol change, or general media support.

## Decision

Store original image bytes as canonical base64 in the complete source bundle, separately from TypeScript modules. Carry them in compiled and linked envelopes, never interpolated into executable JavaScript. Embed the same bytes in the transport JSON so an installed release still consists of exactly `release.json` and `<transportHash>.json`. Supply a defensive read-only byte map to `VisualContext.assets` before calling `create`.

Support only the bounded 24-bit uncompressed Windows BMP subset below initially. It is a real image file format, can be decoded with a small deterministic byte parser, and requires neither a new dependency nor asynchronous platform image decoding. Cost: opaque images only, poor compression, maximum 512 by 512 pixels, and an intentionally narrow import format. PNG/JPEG conversion and transparent images are a later codec checkpoint; do not claim support for them. A raw RGBA source constant or a BMP shipped but never sampled does not meet this design.

Retain SDK `0.1.0`: its existing contract already supplies image bytes as `ReadonlyMap<string, Readonly<Uint8Array>>`; this adds population and enforces isolation rather than changing that API. Do not add an SDK image helper in this checkpoint. Put the fixture's decoder in an ordinary submitted `.ts` module, with CPU conformance tests against the trusted validator. File/source/artifact/transport format versions carry the new requirements; the SDK number alone must never select an asset-capable runtime.

## Wire forms and compatibility

All objects below are strict. Unknown versions and fields fail explicitly. Records must be own-property plain data records; avoid inherited lookups and prototype assignment. Keys use code-unit ASCII order, not locale order, in the new canonical format.

* Legacy source: exactly `{sdkVersion:"0.1.0", entry, files}`. Legacy scene: `{format:"lux-scene", version:1, source:<legacy>, settings, controls}`. Keep old admission normalization and hashing unchanged.
* New source: `{sourceVersion:2, sdkVersion:"0.1.0", entry, files, assets}`. `assets` is a record from logical image path to `{mediaType:"image/bmp", encoding:"base64", data:<canonical base64>}`. Empty assets are valid, so deleting the last asset needs no implicit downgrade.
* New scene: the existing scene fields with `version:2` and new source. Version/source mismatches fail. An assetless v1 open/save remains v1. Adding the first asset explicitly promotes the draft to v2 and displays that requirement; no automatic migration writes on open.
* New compiled artifact: existing fields plus `artifactVersion:2`, `assets`, `assetSetHash`. Here each asset value is `{mediaType, encoding, data, byteLength, sha256, width, height}`; metadata is derived by admission, never trusted from author input. Legacy artifact has none of these new fields. The compiler includes assets in its budget before returning success.
* New linked envelope: `{linkedVersion:2, code, sourceMap, bundleHash, linker, assets, assetSetHash, linkedHash}`. The asset record is copied from verified artifact, not regenerated from disk. Legacy linked envelope retains its exact body/hash algorithm.
* New transport: `{format:"lux-transport", version:2, sourceHash, settings, linked:<v2>}`. New release manifest: existing fields with `version:2` and `assetSetHash`. Settings and fixed controls remain unchanged. Readers require matching version pairs; manifest compares `assetSetHash` with transport's linked envelope as well as current source/linked/settings identities.

New readers accept legacy scenes, artifacts, linked envelopes, transports and releases through separate legacy branches. The new runtime supplies an empty protected map for v1. Legacy installed releases and their runtime directories are never rewritten, rehashed or upgraded; their original readers remain bundled. Old authoring binaries reject scene/source v2; old installed readers reject transport/release v2 instead of silently omitting bytes. No forward compatibility is promised. New asset releases pin a new runtimeId through changed inventory bytes and coexist with old releases. Native installed-source/producer protocols remain v1; render-host lifecycle remains v2 because no native wire field changes. Reject packaging stale asset-unaware JS payloads before publication.

## Admission and image decoding

Apply the same pure validator in source admission, compiler worker, linker, transport reader and worker initialization. Implement a browser-compatible module without Node imports; Node hashing and browser WebCrypto may wrap it. Bundle it into the installed worker and transport reader, or explicitly inventory any emitted helper and copy it in export. There must be no runtime import into an absent checkout.

Limits are cumulative and rejection-based, not truncation-based:

| Resource | Limit |
| --- | --- |
| TypeScript source | Existing 32 files / 1,048,576 UTF-8 bytes |
| Asset count | 4, including duplicate-content paths |
| Each encoded image, after base64 decode | 786,486 bytes (54 + 512 × 512 × 3) |
| All decoded image-file bytes | 1,048,576 bytes |
| Dimensions | 1–512 each, positive integers |
| Total decoded RGBA allocation | 2,097,152 bytes across assets; count before allocation |
| New source compact serialized JSON | 6 MiB; v2 scene serialized JSON (including pretty-print save) 7 MiB |
| Complete request, scene hard read cap | Existing 8 MiB; measure the actual envelope, not only source |
| Artifact / diagnostics / linked / transport | Existing 4 MiB / 128 KiB / 16 MiB / 20 MiB |

Individual ceilings do not guarantee every aggregate combination fits. Reject exact serialized over-budget results even if logical input passed. The compact source and scene margins leave room for ordinary command/document wrapping, but every outer request still checks its exact bytes. Maintain Studio compile stdout's existing 18,000,000-byte ceiling. Do not increase caps to accommodate duplicated base64. MCP JSON text is escaped again by its response envelope: bound the final read response at 16 MiB and document the limit; do not silently omit assets. Audit compiler/link input/result file reads to bound them before JSON parse and again after decoding. Preserve 30-second contained compiler/link worker deadlines, memory limits and candidate timeout.

Logical paths: maximum 240 ASCII characters, `assets/` prefix, lowercase `.bmp` suffix, segments `[A-Za-z0-9_-]+`, case-fold uniqueness; reject reserved Windows device names, `__lux` segments, empty/dot segments, traversal, backslashes, colons, absolute/UNC paths, percent escapes and control characters. They are IDs, never filesystem or URL capabilities. Reject malformed Unicode source text as today. Enforce UTF-8 decoding with fatal errors on scene/transport JSON. A selected import file's absolute path never enters source.

Base64 must use standard alphabet, correct final padding, no whitespace, URL alphabet or data URL prefix; check maximum encoded length before allocation, compute decoded length including padding, then decode and re-encode for exact equality (including pad bits). Count bytes, not JS characters. Reject overlong or empty payloads before image parsing. Derived hashes are lowercase SHA-256 of exact original file bytes. Missing data/metadata, forged metadata or hash disagreement fail; do not substitute a fallback image.

BMP subset: `BM` signature, 14-byte file header, 40-byte BITMAPINFOHEADER, pixel offset exactly 54, reserved fields zero, file length equal to declared file size. Require planes 1, 24 bits/pixel, BI_RGB compression 0, positive width and height, no palette (`biClrUsed`/`biClrImportant` zero). Compute `stride = ceil(width * 3 / 4) * 4` and payload `stride * height` with checked safe integers before allocating; require exact file length `54 + payload`, and `biSizeImage` either zero or that payload. Reject alternative DIB sizes, masks, top-down images, compressed formats, profiles, animation and trailing bytes. Resolution fields may be retained but are not interpreted. Decode bottom-up BGR rows into top-down RGBA with alpha 255, ignoring row padding. Lux interprets the resulting RGB as sRGB. Microsoft documents the header/stride semantics; the tighter restrictions here are Lux policy. [BITMAPINFOHEADER reference](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapinfoheader).

Do not call browser image decoders, fetch, TextureLoader, Blob URLs or platform codec plugins for asset data. TS import rules stay unchanged: importing `.bmp` is rejected. The trusted validator checks every declared asset even if the visual never reads it; malformed unused assets still fail admission. There is no attempt to prove general JavaScript reachability. A missing logical key referenced by the visual is detected during candidate `create` by its required lookup; asset declaration alone cannot prove which keys arbitrary code will request.

## Ownership, identity and runtime behavior

Workspace owns the full immutable source snapshot. Text edits use `{...source, files:...}` and retain assets. An asset replacement is a complete draft change, increments version, marks unsaved/running mismatch, and does not alter the accepted runtime until build succeeds. `submit` and its one-level replacement undo preserve complete old/new source records, including removal and byte changes. Deep-freeze descriptor records (base64 strings are immutable); include source format and every asset descriptor in equality. File tabs remain TS only.

MCP `read` returns full source plus draftVersion. MCP `build` replaces the full source, not a patch; omitted assets in a v2 source are schema failure, not "reuse previous assets". Sending an intentionally legacy replacement deletes assets and must pass candidate creation before promotion. Read/edit/build clients must preserve `assets` and `sourceVersion`. Update discovery and tests so an old schema cannot strip bytes. Save/open/export, failure recovery and restart must carry the same snapshot with no lookup into user files.

For v2, canonicalize property order explicitly as listed above and sort files/assets by ASCII key. Use a single canonical serializer and test byte vectors. Compute sourceHash over complete canonical source, including image bytes. Build assetSetHash over a canonical sorted array of `{path,mediaType,byteLength,sha256,width,height}`; do not include base64 twice. The artifact bundleHash covers all existing artifact fields plus artifactVersion/assets/assetSetHash, excluding bundleHash itself. The linkedHash covers all linked fields except linkedHash itself. Preserve the existing release-manifest pretty-JSON hash algorithm and transport's exact-byte filename hash. Do not reuse the v2 canonicalizer for existing v1 hashes.

Verify descriptor size/hash/dimensions and assetSetHash at every decoded trust boundary, and recompute v2 artifact and linked identities with the same bodies in both child and parent. Changing only a pixel must change sourceHash, assetSetHash, bundleHash, linkedHash, transportHash and releaseId. Hashes establish content consistency, not authenticity; an attacker who rewrites all hashes creates a different identity, not a valid replacement for the expected pinned releaseId. Validation against the installed expected ID remains mandatory.

Worker init receives the full versioned linked envelope (or a verified equivalent retaining every identity field), verifies it and all asset bytes before importing submitted code, then creates a private backing map. Expose a frozen facade implementing ReadonlyMap (`size`, `has`, `get`, `keys`, `values`, `entries`, iterator, `forEach`) with no mutators. `get` and every value-producing iteration yield fresh byte copies, and `forEach` receives the facade as its map argument. Never expose the backing Map, a backing ArrayBuffer, or a mutable shared subarray. Freezing Map/Uint8Array alone is insufficient. The SDK readonly annotation is a compile-time contract; each returned byte array is caller-owned mutable storage, so mutations cannot affect later reads, another candidate, restart or the installed content identity. Test these aliasing cases explicitly.

No new GPU calls are required in the runtime asset plumbing. Fixture code allocates its texture from decoded pixels, sets sRGB input interpretation, and samples it in the existing render path. Disposal releases its texture/material/geometry; worker disposal/termination releases backing byte storage. Repeated gets may allocate caller copies inside the already contained runtime; decoding once in `create` avoids per-frame copies. Verify assets before renderer allocation where possible. Candidate failure follows existing promotion rules; last-good preview stays running and asset diagnostics name the logical path. Export preparation fails before publication on invalid bytes; installed validation fails before visual startup on missing/tampered transport content. A missing runtime asset reference during create must fail the first-frame readiness gate rather than render a placeholder.

## Fixture and acceptance gates

Implement one `required-image` fixture as a `.lux-scene` v2 with `visual.ts`, `bmp.ts` and `assets/checker.bmp` in its source asset record. Generate a 3-by-2 24-bit BMP once as test input: asymmetric red/green/blue top row and cyan/magenta/yellow bottom row, deliberately exercising row padding and orientation. The fixture's create function must obtain `context.assets.get('assets/checker.bmp')`, throw `Missing required asset: assets/checker.bmp` if absent, decode it in `bmp.ts`, and create a Three `DataTexture` used by the displayed plane/material. Use nearest filtering and explicit orientation/color handling; six solid test regions make failures visible. No embedded pixel array or fallback pattern in `visual.ts`/`bmp.ts`. The base64 in the asset record is the only pixel source. Exact Three constructor/constants/import choices are checked by the existing pinned compiler, not new allowlisted packages.

1. CPU validator vectors: valid padded rows, max dimensions, wrong signatures/offsets/sizes, truncated header/pixels, negative/oversized dimensions, palette/compression/profile variants, invalid base64/padding, duplicate folded paths, dangerous paths, unknown fields/versions, quotas, forged metadata. All invalid vectors fail before large allocations. Decode expected pixels using the fixture decoder and trusted parser independently.
2. Workspace/session/MCP tests: byte-only replacement dirties draft and changes running match; failed replacement retains old snapshot; successful replacement and undo restore exact image bytes; text edit, source read, reopen/save/export and guarded stale builds preserve complete source. Boundary-size tests include JSON escaping and MCP read wrapping.
3. Compiler/link CPU integration under existing containment: assets cannot be TS imports or dependency paths; assets survive compile/link; pixel-only change changes the identity chain; deletion/mutation of an artifact/linked asset or metadata is rejected. Existing v1 fixtures still compile/link under new tools, without rewriting their saved source documents.
4. Package tests without graphics: export to exactly two release files; remove transport, tamper one byte, alter a claimed image hash/metadata, remove assets while keeping old IDs, add an unlisted sibling, mismatch format versions, substitute stale runtime worker, and mismatch expected release/runtime IDs. Each rejects without replacing old installed content. New validators read existing immutable v1 release fixture bytes unchanged.
5. Separately authorized runtime evidence: create/capture the fixture, assert six interior pixel regions with tolerances, revise only image pixels and show the changed output, restart and capture, export/install and cold-open with Studio closed, network unavailable and authoring files absent. Exercise two instances and restore old/new releases together. Record input asset hashes, source/linked/transport/release/runtime identities and capture metadata. Deleting the image key must fail candidate readiness; corrupting installed image data must fail installed validation. CPU-only passing tests cannot substitute for this consumption/offline evidence.

Use the existing compiler, scene-file, source-workspace/authoring-session, MCP, transport-release/prepare and export-package test suites rather than an unrelated sample harness. This design checkpoint runs none of the graphics/native/host gates. Implementation is complete only when bytes visibly drive the output and survive the full chain; merely populating a map is insufficient.

## Delivery order and import UI

First implement/test versioned contracts, bounded parser and identity functions; then workspace/MCP round-trip; then compile/link and runtime byte-map plumbing; then transport/release compatibility and stale-runtime checks. Add the consuming fixture and CPU gates alongside those changes. Runtime evidence follows the separate host/GPU safety process.

For the initial checkpoint, opening the supplied self-contained scene and whole-source MCP replacement provide a usable byte entry path. A minimal subsequent **Import BMP** action selects a local file through Studio's trusted dialog, bounded-reads one regular file (no directory traversal, reparse links, remote URL or automatic watcher), validates it, and atomically adds/replaces its source asset descriptor. Default logical name derives from a sanitized basename with explicit collision handling; cancel or failure leaves draft unchanged. Replacement increments draft version and needs Build to affect preview. Show path, dimensions, byte count, dirty state and removal in a small asset list; no binary editor or base64 text area. Preflight the entire resulting source/scene serialized budget before committing the change. Import UI must not be marketed as general image import until another codec is approved and tested. No product question blocks the bounded recommendation; the recorded format and size costs are the deliberate first-step tradeoff.
