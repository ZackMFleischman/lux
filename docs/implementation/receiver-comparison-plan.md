## Current evidence and selected approach

The timing helper and strict inspector are integrated; native source input hashes, compiler settings, eight Release binaries and deterministic generated fixtures are retained in `docs/conductor-onboarding/receiver-timing-main-*`. Those builds selected the receiver DLL and CPU tests only. They did not build the producer `.node`, render worker or an installed package.

Read-only main inspection found no `native/vendor/node/node-v24.20.0/include/node/node_api.h`, `native/vendor/node/node.lib`, `native/build/Release/lux_texture_bridge.node`, `apps/render-host/src/main.cjs` or `apps/render-host/src/compiled-worker.js`. `node_modules/electron/package.json` exists. Missing emitted files require a current source build; copying an old package or trusting a capability marker is insufficient. Retained `.worktrees/transport/native/vendor/node` contains node.lib, headers.tar.gz and headers whose node_version.h declares24.20.0. Their local bytes and historical origin still need an explicit manifest/attribution before use. Filename/version strings alone are not distribution authenticity evidence. Initial inventory is `docs/conductor-onboarding/receiver-comparison-prerequisites.json`.

`native/CMakeLists.txt` links the bridge to those exact Node headers/library and uses the same pinned VS18/x64/MSVC14.50.35717/SDK10.0.26100.0 build. `tools/gpu-spike/build.mjs` emits main.cjs with Node type stripping, bundles runtime validation and visual-worker with esbuild, and syntax-checks four existing entrypoints. It is not a semantic TypeScript check or a graphics run. `scripts/export-resolume.mjs` validates capabilities, prepares an immutable transport release, copies regular Electron/runtime/native files and delegates package construction to `packages/export/src/package.cjs`. The package contract hashes its bytes but does not record which compiler/source produced them. `test-installed-package.mjs` actually runs a packaged installer/supervisor; it is not part of CPU-only file preparation below.

Choose a shared freshly built runtime payload, then two receiver DLLs from exact source variants. Reverting R2a commits would also perturb shared headers/tests/documentation and risks replacing R1/timing control flow. A permanent runtime switch would enlarge shipped behavior for a diagnostic. Instead, the later baseline leaf uses a private, reviewed one-statement source removal; production main retains the accepted treatment. All other common runtime bytes are built once and copied identically into both packages. Source equality and package file comparisons establish the controlled difference; absolute build paths/PDB details inside independently linked DLLs are recorded as build metadata, not hidden causal variables.
