## Ownership and choices

`nested-validate.ts` authenticates `ValidatedNestedGraph` in a private WeakSet. `nested-plan.ts` accepts that object and returns a detached deeply frozen `NestedExecutionPlan`; the returned DTO has no authenticity or source provenance. It already supplies reachable leaf order, exact structured paths, metadata, wired inputs, complete initial controls, final output and public bindings including inactive targets. Do not reconstruct these rules in the scheduler or treat a cloned DTO as authority.

`parameters.mjs` owns numeric schemas, complete snapshots and live partial patches. `seed.ts` owns the existing uint32 Mulberry32 stream. `clock.ts` owns animation-clock sampling, playback and reset epoch; it supplies no scheduler tick. The future outer adapter owns tick assignment and the conversion from clock snapshots to the frame protocol below. `single-image.ts` and SDK `ComponentInstance` remain the separate C02 root-output bridge with `EmptyInputs`. Neither is assignable to the graph factory or resource API proposed here. No edits to these owners, the SDK barrel/profile, compiler, Studio, MCP, persistence or shipped skill are part of C03c1.

Three approaches considered: accept arbitrary execution DTOs and duplicate full validation in the runtime (two competing planners); add executable identity to the C03b DTO (changes a delivered pure planning contract); or create a separate runtime capability from already authentic input. Select the third: small ownership boundary, no C03b edits, no serialized capability. Opaque local admission proves only that this process ran the planner; a later trusted factory adapter must independently bind definition hashes to reviewed source bytes. It is not a sandbox against hostile JavaScript, process compromise or replaced intrinsics.

### Exact derivation and known answers

Algorithm identifier `lux-node-rng-v1`: concatenate ASCII/UTF-8 `lux-node-rng-v1` followed by byte `00`, scene seed as exactly four little-endian bytes, path count as one byte, then each UUID as exactly 36 ASCII bytes in outer-to-inner order. Total bytes are `21 + 36 * path.length` (57–309). Feed every byte into FNV-1a-32: start `2166136261`, then `h = Math.imul(h ^ byte, 16777619) >>> 0`. The resulting uint32 initializes the unchanged `SeededRandom`. Each `next()` is its existing Mulberry32 output in `[0,1)`. `reset()` repeats that stream's original derived seed and takes no replacement seed. This is creative determinism, not cryptography or collision-free identity: two paths can collide in 32 bits but still own separate mutable instances and stream state.

Let A=`00000000-0000-4000-8000-000000000001`, B=`00000000-0000-4000-8000-000000000002`, U=`ABCDEFAB-1234-4ABC-8DEF-ABCDEFABCDEF`, and L=`abcdefab-1234-4abc-8def-abcdefabcdef`. Expected output words are `next() * 4294967296`, exactly representable integers:

### C03c2: closed fake resource authority

Intended owners: new `packages/runtime/src/graph/resources.ts` for the authority and `tests/runtime/graph-resources.test.ts` plus `graph-resources-async.test.ts` for CPU evidence; runtime types live beside their owner, with no SDK export. Its exact implementation plan must expose distinct scheduler-only, callback-only and fake-backend-test surfaces. Do not give authored callbacks scheduler admission, release, identity minting or arbitrary retain capabilities.

`ResourceHost` is a trusted per-runtime authority with immutable configuration `{generation, sceneSeed, initialClockEpoch, width, height, format:'rgba8unorm', colorSpace:'linear-srgb', alphaMode:'premultiplied'}`. Generation and epoch are nonnegative safe integers, seed uint32, dimensions integers 1–4096, product <=16777216. It can attach to exactly one graph runtime. Each runtime/host has a fresh unguessable owner object; matching numeric generation alone is not authority. CPU images carry descriptor/counters only, no pixel allocation or claim of rendering correctness. All code outputs of image kind use these exact host dimensions/format in this first profile; arbitrary per-node sizes, format conversion and resize remain gated.

An evaluation scope is tied to owner, generation, clock epoch, frame evaluation ID, producing node path and declared output ports. Resource tokens are frozen opaque objects registered in a private WeakMap, with immutable descriptor/version data accessible only through validated authority operations. Versions are monotonic safe integers within the host and never reused, even after release; exhaustion rejects before issue. Signal descriptors are finite numeric values with exact C01 unit (including null) and clock `frame`. Image descriptors must equal host width/height/format/color/alpha before any consumer/backend work. No duck typing, cloned token, foreign host, wrong port kind, earlier epoch, released token or stale evaluation scope is accepted.

The authority precomputes exact consumers from admitted `PlannedInput` addresses `(destination path,input port)`, keeping parallel input ports distinct, plus final presentation and explicitly requested capture readers. An output may only be returned for its declared producer port, and each required output key appears exactly once. No arbitrary output token reuse under another producing port. A graph port alias is resolved in the existing plan to one actual leaf output and therefore shares that output's token. A later node receives a fresh **consumer view** authorized only for its own path/input ports, not the producer token's issue/release operations.

Callback surface supports reading a signal value, requesting a fresh signal output, and requesting a fresh image output via the trusted backend. Transforming an input image always requests a new output allocation; this version offers no in-place or copy-on-write shortcut. One allocation per declared output port per evaluation; no unbounded hidden allocations. Backend dispatch is reserved and recorded synchronously before invoking backend code, including synchronous throw/reentry; observe its promise even if the callback does not await it. Closing a callback scope prevents new work but does not mark its already issued work settled.

For every allocation maintain separate obligations: producer backend completion, each authorized consumer callback completion, each consumer's recorded backend completion, cached-output pin, and presentation/capture holds. The scheduler cancels obligations for never-started downstream consumers only when it has closed their authority and knows they dispatched no backend work. Release physical storage exactly once after all remaining obligations settle. A failed callback/output validation rejects the frame but cannot erase pending backend/capture obligations. Backend rejection is settled failure; a promise that never settles retains ownership. Logical invalidation makes tokens unusable immediately while physical release still waits.

Published output is a frozen `FrameOutput` reader with idempotent `release(): void` and bounded `capture(): CaptureHold`; it carries no mutable image data. Capture holds have idempotent release and keep an allocation alive independently of the frame reader. Releasing a reader prevents new captures from it. New presentation readers over a cached allocation are fresh identities; released readers cannot be revived. The authority limits live allocations to 8192 (512 leaves ×16 outputs), pending backend operations to8192, graph input-reader obligations to4096, external live frame readers to16 and capture holds to16 total per runtime. Reserve count before creating a promise/token; cap+1 rejects before backend dispatch or retaining more state. At resource pressure a new frame fails with an explicit capacity error rather than evicting held storage. These CPU accounting limits do not establish GPU memory budgets; the real backend profile must add a byte budget.

The c2 evidence gate uses explicitly controlled deferred promises and a release event ledger, not elapsed sleeps. Required literals: diamond A has two consuming ports and releases after both callbacks and their backend obligations; one consumer's unawaited deferred work delays release after its callback throws; an output token with wrong dimensions never reaches consume; copied/foreign/released/previous-epoch tokens reject; a capture held across frame disposal retains storage; duplicate reader/hold release does not decrement twice; synchronous backend reentry observes the reservation. Construct direct authority fixtures under the trusted test surface at each exact cap and cap+1; do not infer all 8192 allocations are simultaneously constructible in a valid graph under every C03b bound. Report authority cap coverage separately from end-to-end reachable graphs.

### C03c3: serial frame scheduler and live controls

Intended owners: new `packages/runtime/src/graph/runtime.ts`, `runtime-types.ts`, `tests/runtime/graph-runtime.test.ts`, `graph-runtime-lifecycle.test.ts` and shared test-only fake factories. The detailed c3 plan must lock exact resource API signatures delivered by c2, rather than inventing a second authority.

Internal interfaces retain `update/evaluate/reset/dispose`. `ComponentFactory.create(definitionHash, context)` returns one new instance for each reachable path, in the existing deterministic plan order. Context includes exact path, read-only normalized metadata, host settings and a private path RNG; it cannot issue resources before an evaluation. The trusted adapter guarantees hash-to-source correspondence outside this CPU contract. A reused object for two paths rejects. `NodeFrame` supplies `{clockEpoch,tick,timeSeconds,deltaSeconds,controls,controlSequence}`; controls are that path's complete effective immutable snapshot. `update(frame)` and `reset({seed,controls})` may return void or a promise; `evaluate(inputs, context)` returns the exact declared output map or a promise thereof; `dispose()` may return void or promise. Inputs are authority-issued views for declared ports; evaluate context includes the same NodeFrame and scoped output/resource operations. C02's zero-input/image-only instance receives no implicit adapter.

`createGraphRuntime(plan, factory, resources)` is the only scheduler entry point. It requires the exact c1 capability, matching unattached host and complete callable factory before invoking authored code. Return a frozen runtime handle with a `ready` promise, `frame(input)`, `setNodeControls(batch)`, terminal `dispose()` and c4's separately gated reset. Returning the handle before awaiting initialization allows cancellation during create. It creates no clock, timer or autonomous loop. Frames and initialization run through one serial operation chain; at most64 queued frame/reset operations, reserved before promise creation. New calls after terminal state reject. Dispose sets terminal state synchronously, before waiting for that chain.

First frame protocol is intentionally explicit, using `{kind:'advance'|'present',clockEpoch,tick,timeSeconds,deltaSeconds}`. Initial frame baseline is host initial epoch/tick0/time0; `present` at that baseline is allowed. `advance` requires same epoch, exactly previous simulation tick+1, nondecreasing finite time <=Number.MAX_SAFE_INTEGER seconds, and `deltaSeconds === timeSeconds - previousSimulationTime` with finite nonnegative delta. Caller computes that subtraction; there is no tolerance/clamping or inferred skipped tick. `present` requires current simulation epoch/tick/time and delta0. This is a paused/presentation request, so it never calls update or draws simulation RNG. Switching outer playback to paused uses present; playback itself is not a conflicting extra frame field. The outer adapter must enforce that present is used for paused redraw; this CPU runtime does not inspect a device or RuntimeClock instance.

A repeated advance request with exactly equal admitted fields at the current simulation tick is an idempotent retry: no control transactions are consumed and no callbacks repeat; it returns a fresh presentation reader to that advance's retained result. Retain exactly one additional pin for the last successful advance's final allocation until the next advance, reset or terminal disposal. A later present with changed controls does not replace this retry result. This pin is separate from the per-node cache and counts toward the same allocation/reader budgets. Same advance tick with different time/delta/epoch rejects before any state mutation. A new epoch is accepted only through c4 reset; c3 rejects it. New advances call each stateful node's update once in plan order, then evaluate its outputs after predecessors; stateless nodes never receive update. Present evaluates the graph without update, allowing effective live controls to redraw with frozen simulation time. Evaluate must be presentation-pure: the private simulation RNG is enabled only during create, stateful update and reset, and throws if used from evaluate. Authored hidden state mutation cannot be sandboxed by this contract and is a future execution-profile responsibility.

Cache key per node contains outer generation, exact structured path, definition hash, clock epoch, tick, each ordered input resource version, and that node's effective control sequence. One cached result per reachable node. Simulation updates happen once per accepted advance even if its later frame fails; a callback/resource failure makes that runtime terminal, so it never retries partially advanced state. Unchanged repeated present can reuse the cached allocation; a changed control sequence re-evaluates the changed node and descendants through input versions, while unaffected nodes reuse caches. All reused leases get current evaluation/consumer views via the authority; old evaluation-scoped views are never passed into a new callback. Cache pins cannot outlive epoch invalidation. No cross-epoch output reuse or assumption that logical nodes equal GPU passes.

`setNodeControls(batch)` accepts 1–512 unique **reachable leaf paths**, each with a nonempty numeric/live partial patch validated using `validateControlPatch` against that leaf's C01 metadata. It does not accept graph/root paths, pruned paths, public-control IDs inferred from leaf names, structural costs, events, clamping or implicit intensity. A future public binding adapter must expand graph/root controls explicitly, disclose inactive bindings, and reject overlapping writers. Validate the entire ordinary-data batch before queuing any value, with <=256KiB canonical bytes and existing descriptor/depth/value safeguards. Within a batch reject duplicate paths; across accepted calls FIFO last write wins for overlapping values. Limit pending transactions to64 and aggregate canonical queued bytes to1MiB, reserve before copying into the queue, and report capacity synchronously without changing prior transactions.

Each frame call captures the current transaction watermark synchronously. At its execution boundary, a new advance or present applies all queued transactions through that watermark atomically before callbacks. Calls arriving after that watermark wait for the next frame; idempotent advance retries consume none. Compare numeric values without step quantization; an effective change increments that path's safe integer control sequence once for the complete boundary, a no-op does not. Validate sequence headroom before applying any path; exhaustion requires a new runtime generation. Controls persist after a frame failure for diagnostics but the runtime is terminal. No create/reset occurs from a live patch. Separate same-definition paths retain distinct snapshots, sequences, counters and random streams.

Mandatory legal diamond: root contains A→B, A→C, B→D(left), C→D(right), final D.image. A produces number signal, B/C use the same definition with one signal input/output, D has two signal inputs/image output; all lifecycle metadata, including root, is stateful. All signal unit=null/clock=frame; images linear-srgb/premultiplied. Initial gains A=1/B=C=2. First advance increments each state counter from0 to1. ## Terminal lifecycle, reset and candidate gates

C03c2/c3 must already handle terminal failure and disposal; these are not deferred until reset exists. Capture a usable disposer as soon as each create result becomes available, before validating its remaining methods. Mark disposal attempted before invoking it; never call it again even if it throws/rejects. If a malformed create result supplies no callable own disposer, record that cleanup is unavailable; do not fabricate successful authored cleanup. When create rejects without returning an instance, record no created instance for that path. All earlier created instances still require cleanup. Cancellation while a create promise is pending waits for it; a late returned instance is disposed without publishing ready or any frame.

On explicit dispose or first callback/resource failure, atomically enter terminal state, close issue/publication authority and reject queued jobs. Drain the currently executing callback and every already registered backend obligation, including work it abandoned. Then release cache pins and cancel never-started consumer obligations, await external frame/capture readers and their backend work, and attempt each captured disposer once in reverse creation order. Preserve the original operation error as primary and append separate bounded cleanup errors (one per instance, at most512, each message<=1024 characters). One failing disposer must not skip remaining safe disposal attempts. Repeated dispose calls return the **same promise object**, so the public method must return stored completion directly rather than an `async` wrapper that creates a different promise. No publication occurs after the terminal flag, even if a callback later returns a structurally valid output.

No timeout is treated as settlement. A stuck callback, backend promise, capture holder or disposer keeps completion pending and ownership visible. The outer supervisor may later terminate the process under its own explicit policy; that boundary cannot prove authored cleanup, physical GPU drain or orderly resource release. New host work never reuses those in-process tokens.

C03c4 reset contract: full reset only, serial and mutually exclusive with frame execution. Request `{clockEpoch: current+1}` with checked safe integer, at the same scene seed and current effective values; reject other epochs. At its boundary apply pending controls through its captured watermark, invalidate cached views, drain backend/external reader obligations, reset each RNG to its path-derived seed, then call every reachable instance's reset in plan order with that seed and current controls. Initial reset baseline is tick0/time0, next frame may present there; no control defaults are reinserted. A reset failure terminates that runtime and performs safe terminal cleanup. Reset never recreates instances or assumes state transfer. Tests must establish that the authored fixture's reset uses the provided controls and repeats known seed output; passing a seed argument alone does not prove state reset. Cancellation during reset uses the same terminal/drain rules.

**Targeted reset is not exposed.** Its explicit future policy is downstream closure: selected reachable paths plus all transitive consumers reset once, invalidate their downstream output caches, and retain unaffected upstream state. Because this would create mixed simulation histories under one epoch, exposing it additionally requires a separately reviewed per-subgraph epoch/cached-input policy. No `resetNode`, optional target argument or UI shortcut is admitted by c1–c4. Reordering an equivalent admitted graph is not a source/topology update and must retain active instances; live controls already do so through c3.

C03c5 candidate promotion belongs to a separate outer owner `packages/runtime/src/graph/runtime-slot.ts` and `tests/runtime/graph-runtime-slot.test.ts`, planned only after reset/lifecycle acceptance. It prepares a complete new authentic plan and hash-bound factory/host with a fresh outer generation. Candidate initialization, output validation and a successful baseline presentation finish privately before any promotion; candidate controls are supplied by the core adapter's explicit saved-intent reconciliation, never guessed here. A candidate failure disposes only the candidate and preserves active runtime state/reader. No source/topology edits mutate live instances. Promotion switches a slot pointer atomically at an outer frame boundary, reports `simulationReset:'full'` and the new generation/epoch, closes old publication authority, and drains/disposes the retired runtime under the same reader/lease rules. Old published readers may retain old allocation ownership until released but cannot publish new frames. At most one active, one candidate and one draining retired runtime; reject another candidate while retired ownership persists. This combined capacity and byte/GPU feasibility requires review before real backend use. No partial promotion, reallocate parameter, change-cost state transfer or best-effort topology graft is included.
