# Bounded JPEG codec CPU slice

`src/jpeg.mjs` supplies bounded JPEG decoding to `src/index.mjs`, Studio image
workers and the pre-import runtime image map. Compiler/linker inventories pin the
actual codec implementation. CPU decoding evidence below is separate from the
required Studio/installed-host playback checks.

`decodeJpeg(bytes, {maxRgbaBytes?})` returns `{width,height,colorSpace:'srgb',
alphaMode:'straight',data:Uint8Array}`. Alpha is verified as 255. A private bounded
copy retains the exact original file; EXIF orientation 1..8 is applied only to
derived RGBA pixels and dimensions. `validateJpeg` performs full decode and returns
`{width,height,byteLength,rgbaByteLength}`. A caller can provide the remaining
aggregate RGBA budget, checked before the decoder allocates coefficient buffers.

## Supported subset and bounds

- SOF0 baseline and SOF2 progressive, 8-bit samples, one or three components,
  width/height 1..512, file <=786486 bytes, sampling factors 1..2, <=10 MCU blocks.
- <=1024 markers, <=16 scans, <=128 Huffman table definitions, <=64 KiB APP/COM
  payload. Segment offsets/lengths, tables/symbols/selectors, progressive band and
  refinement ordering, quantization references and restart count/sequence are
  checked before general decoding. Every component's bands must be present.
- Quantization tables cannot be duplicated or redefined after scans. Baseline
  requires 8-bit quantization; progressive also accepts nonzero 16-bit tables.
- Ordinary JFIF/YCbCr, grayscale, and explicit three-component Adobe transform
  0 (RGB) or 1 (YCbCr), version 100. Conflicting declarations, ICC profiles,
  unsupported APP0/Adobe variants, arithmetic/lossless/hierarchical modes,
  CMYK/YCCK and ambiguous untagged component layouts are rejected.
- EXIF TIFF header/IFD0 bounds, <=128 entries, inline SHORT orientation count one,
  valid orientations, duplicate metadata and pointer boundaries are checked. Other
  EXIF fields are not interpreted and no pointers are followed. No color management
  is performed; export sRGB without an embedded ICC profile for this subset.

The pinned decoder call is jpeg-js 0.4.4 with `useTArray:true`,
`formatAsRGBA:true`, `tolerantDecoding:false`, `maxResolutionInMP:0.262144`,
`maxMemoryUsageInMB:32`, plus the preflight-selected color transform. The upstream
memory accounting is approximate. Neither this accounting nor finite scan budgets
provide a preemptive CPU deadline.

## Pinned decoder corrections

`patches/jpeg-js@0.4.4.patch` retains the upstream algorithm and notices, with
small boundary corrections exposed by hand-derived regression fixtures:

1. The single-component restart loop stops at the final expected MCU, matching the
   existing interleaved branch; a partial final restart interval is valid.
2. Strict mode checks one-fill padding and requires an immediate next marker,
   instead of silently skipping arbitrary unused entropy bytes.
3. Strict mode rejects baseline/progressive initial AC runs or coefficients beyond
   the block/band and EOB runs extending past a scan/restart boundary.
4. Strict refinement blocks must finish in a completed state or a legitimate EOB
   state, rejecting unfinished zero/new-coefficient runs at block boundaries.
5. Legal FF fill bytes preceding restart/final markers are consumed without
   changing original file bytes or relaxing entropy padding checks.

These are Lux modifications, not an upstream release. The pnpm lockfile records
the dependency integrity and patch hash. The decoder is imported directly from
`jpeg-js/lib/decoder.js`; the browser bundle test excludes the encoder entry point.
The copied BSD package license, Apache-2.0 decoder notice and Apache-2.0 license
must accompany distributions. Installed validator/worker license shipping and
codec inventory pinning remain integration work.

Sources: [jpeg-js decoder](https://raw.githubusercontent.com/jpeg-js/jpeg-js/v0.4.4/lib/decoder.js),
[decode options](https://github.com/jpeg-js/jpeg-js/tree/v0.4.4#decode-options),
[JPEG T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf).

## Verification and responsiveness

```sh
node --test --test-isolation=none tests/assets/jpeg-codec.test.mjs tests/assets/jpeg-browser.test.mjs
node tests/assets/jpeg-benchmark.mjs
```

Fixtures under `tests/assets/fixtures/jpeg/` were independently generated by
Pillow 9.5.0/libjpeg using the checked-in regeneration script. Tiny restart and
entropy fixtures are hand-derived from T.81, with literal uniform-128 pixel
expectations. Tests cover baseline/progressive pixels, grayscale, both EXIF endian
modes and all orientations, alpha, preserved original bytes, malformed metadata/
tables/frames/scans, caps, restart cadence, padding, unused entropy and excess
coefficient/EOB runs. This is targeted regression evidence, not exhaustive JPEG
conformance or fuzzing coverage. Browser execution uses no platform image codec.

2026-09-12, Node 24.12.0, Windows, Intel i7-10750H, 20-run decoder-only measurements:

| Input | File bytes | Median ms | Maximum ms |
| --- | ---: | ---: | ---: |
| 512x512 progressive pattern | 72048 | 22.57 | 67.28 |
| Two 512x512 patterns | 72048 each | 43.41 | 47.87 |
| 512x512 noisy progressive | 433177 | 67.69 | 95.23 |
| Four 362x362 noisy progressive | 222530 each | 141.22 | 169.78 |
| Forged height | 72048 | 0.05 | 0.34 |

A separate **fresh-process** noisy 512x512 decode took **118.39 ms**, exceeding
the design's proposed 100 ms per-image target. The noise batch above ran after
the pattern batches and is therefore warm. RSS deltas of the five batches were
approximately 33.5/4.0/33.0/2.5/1.5 MB; these are GC-sensitive process deltas,
not peak-memory limits or evidence of leaks.

Keep full decoding off Studio's per-keystroke synchronous source validation.
The next coherent integration is asynchronous worker admission that returns an
immutable verified source snapshot, with a bounded trusted decoded cache for
unchanged assets. Source edits should reuse previously admitted asset identity;
changed/imported bytes require fresh worker admission. Build/link/transport and
render-worker trust boundaries must still validate their own received originals.
Full source timing (base64, hashing and repeated calls) remains unmeasured. No
renderer, Studio, native host or graphics test was run for this slice.
