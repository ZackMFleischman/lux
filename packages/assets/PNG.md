# Bounded PNG codec CPU slice

`src/png.mjs` is an opt-in adapter. `src/index.mjs`, existing BMP admission,
source paths/media unions, identity branches, compiler/linker inventories and
runtime capability markers remain unchanged. This slice does **not** enable PNG
assets in Studio or demonstrate asset playback. See `JPEG.md` for the separate
opt-in JPEG adapter.

## API and supported input

`decodePng(bytes, {maxRgbaBytes?})` returns `{width,height,colorSpace:'srgb',
alphaMode:'straight',data:Uint8Array}`. Pixels are top-down RGBA8, with RGB retained
even when alpha is zero. Every call copies the original bytes before inspection;
it neither rewrites caller bytes nor transforms the decoder input.
`validatePng` performs the same full decode, discards pixels, and returns
`{width,height,byteLength,rgbaByteLength}`. It is not header-only validation.

Supported: static noninterlaced PNG, grayscale/RGB/grayscale-alpha/RGBA at depth 8,
indexed color at depths 1/2/4/8, palette alpha, grayscale and RGB `tRNS`. Untagged
images are treated as sRGB. The adapter accepts sRGB, gAMA=45455, and the standard
sRGB cHRM values. Other profiles, 16-bit input, Adam7, APNG and compressed metadata
are explicitly rejected. Export as noninterlaced 8-bit sRGB PNG for this subset.

Limits: original bytes <=786486, width/height 1..512, <=256 chunks, <=64 KiB total
ancillary payload. Checked chunk offsets/order/duplicates/CRC cover the complete
file, with contiguous IDAT and final empty IEND and no trailing bytes. Only IHDR,
PLTE, tRNS, IDAT, IEND, sRGB, gAMA, cHRM, pHYs, tEXt and tIME are admitted.

Pako's low-level zlib API receives at most 4096 input bytes per call and a fixed
16384-byte output scratch. The wrapper bounds output to the exact scanline size
plus one sentinel byte, checks filter bytes, Adler/termination/progress, rejects
dictionaries, truncation and extra streams/tails, and releases state in `finally`.
No inflated chunks are accumulated by preflight. The same private original bytes
then enter fast-png with CRC enabled; output dimensions/depth/channels/length and
palette references are independently checked. RGBA conversion reads transparency
from the checked original chunks. `maxRgbaBytes` supplies the caller's remaining
aggregate RGBA budget, checked before inflation or pixel allocation. This slice
does not implement four-asset records, aggregate original-byte accounting or cache.

## Exact dependency closure and patch

Pinned dependencies: fast-png 8.0.0, pako 2.1.0, fflate 0.8.2 and iobuffer 6.0.1.
Scoped pnpm overrides pin fast-png's two transitive dependencies. The lockfile
records registry integrity and the fast-png patch hash. The browser bundle test
executes an in-memory IIFE without platform codecs or runtime imports and checks
that the PNG encoder and Node worker payloads do not contribute emitted bytes.

The narrowly scoped `patches/fast-png@8.0.0.patch` corrects an upstream tRNS length
check in both shipped JS and source TS. Upstream compares the three RGB color-key
components against image pixel count and wrongly rejects valid 1-/2-pixel images.
The patch replaces that comparison and the permissive even-length check with the
spec's exact two-byte grayscale / six-byte RGB lengths. Original files, decoder
algorithm and notices remain unchanged. Tests cover tiny RGB color keys and all
nearby invalid lengths. This is a Lux patch, not an upstream release.

## Verification and measured limits

Run from the checkout root:

```sh
node --test --test-isolation=none tests/assets/assets.test.mjs tests/assets/png-codec.test.mjs tests/assets/png-browser.test.mjs
node tests/assets/png-benchmark.mjs
```

Fixtures are generated by an independent test writer using Node zlib and literal
scanlines, without the production encoder. Coverage includes straight hidden RGB,
all five filters, odd packed-palette rows, tRNS, caps, CRC/Adler, tiny-IHDR expansion,
metadata/chunk structure, unsupported profiles/modes, duplicate/trailing chunks,
dictionary and multiple/truncated zlib streams. The differential corpus contains
27 valid zlib streams (stored/fixed/dynamic strategies and varying levels/sizes)
plus 648 deterministic bit mutations. Accepted streams are compared to native
zlib and fflate. This is bounded regression evidence, not proof against every
malformed stream or an exhaustive fuzzing result.

On 2026-09-12, Node 24.12.0, Windows, Intel i7-10750H, 20 consecutive iterations:

| Input | File bytes | Median ms | Maximum ms |
| --- | ---: | ---: | ---: |
| 512x512 RGBA pattern | 5945 | 25.35 | 56.42 |
| 512x512 noisy grayscale | 262804 | 8.76 | 16.21 |
| Four 362x362 RGBA pattern images | 3828 each | 33.33 | 71.91 |
| Tiny IHDR / four-million-byte expansion | 3955 | 0.13 | 0.58 |

Per-batch RSS deltas were approximately 1.7/25.9/7.5/0.9 MB respectively. These
include JavaScript allocation/GC behavior and are not peak-memory bounds or leak
claims. First maximum-RGBA decode was 55.87 ms. Decoder-only measurements satisfy
the proposed 100 ms/asset target for this measured corpus; full source admission
with base64, hashes and repeated trust-boundary calls remains unmeasured. No
synchronous JavaScript implementation provides a preemptive CPU deadline.
